# Spring Boot

## Inversion of Control (IoC)
Это принцип, согласно которому управление объектами и их зависимостями передаётся приложению, а не осуществляется вручную в коде (Программа сама себя настраивает, реализуется в Spring за счёт Application Context)

### Application Context
Это контейнер, который управляет жизненным циклом объектов программы (бины), внедрением зависимостей и обработкой аннотаций и конфигураций

Пример: нужно создать экземпляр класса UserService. Вместо того, чтобы создавать его через new Class(...), зависимости для него берутся из контейнера, Spring создаёт их зависимсости и прокидывает их в сервис -> связность компонентов уменьшается. После создания, UserService также будет помещён в контейнер для создания будущих объектов

### Способы создания бинов
Для того, чтобы Spring создал бин и поместил его в Application Context, необходимо пометить, что данный класс нужно создать

Есть несколько способов:
- Использование аннотаций (@Component (от которой наследуются все последующие аннотации), @Service, @Repository, @RestController и т.д)
```java
@Service
public class UserService {
    private final UserRepository userRepository;

    @Autowired 
    // эта аннотация над конструктором нужна чтобы Spring использовал именно этот конструктор для внедрения зависимостей
    // если класс только один её использование необязательно
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}
```
- Аннотация @Configuration (Используется для создания специального конфигурационного класса, в котором описывается создание бинов)
```java
@Configuration
public class AppConfig {
    @Bean
    public UserRepository userRepository() {
        return new UserRepository;
    }

    @Bean
    public AuthenticationService authenticationService() {
        return new AuthenticationService;
    }
    // и так далее
}
```
- Xml Configuration (устаревший способ)

## Dependency Injection
Позволяет внедрять зависимости извне, а не создавать их внутри самого объекта
Помогает уменьшить связность компонентов, улучшить тестируемость и модульность кода

Пример: Нужно создать объекта класса UserService

### Способы DI
@Autowired (основная аннотация для указания внедрения зависимостей)
- Constructor Injection (Самый часто используемый. конструктор помечается @Autowired, Spring понимает что зависимости нужно взять из Application Context)
- Field Injection (не рекомендуется, зависимость внедряется напрямую в private поле с помощью Reflection API уже после того, как объект был создан через конструктор. Поле нельзя сделать final. Без Spring-контекста эти поля останутся null. Слишком легко добавить 15 зависимостей в один класс и не заметить, что нарушен принцип единственной ответственности)
```java
@Service
public class UserService {

    @Autowired
    private UserRepository userRepository;

    public UserService() {

    }
}
```
- Setter Intection (можно использовать для необязательных зависимостей, поля также нельзя сделать final. Почти не используется)
```java
@Service
public class UserService {
    private UserRepository userRepository;

    public UserService() {

    }

    @Autowired
    public void setUserRepository(UserRepository userRepository) {
        this.userRepository = userRepository
    }
}
```

# HTTP и Spring Web

## HTTP
HTTP – протокол передачи данных в сети интернет
протокол - набор правил (клиент - пользователь, сервис отправляет запрос, ответ приходи от сервера. У каждого протокола чёткий набор правил: что может быть в ответе, в запросе и т.д)
Почти весь интернет работает на HTTP, в веб разработке Java используется именно он

## Spring Boot Starter WEB
Стартер из Spring Boot, который даёт инструменты для приёма и обработки HTTP запросов. Сильно упрощает работу с HTTP, обработку ошибок, валидацию и тестирование  


## HTTP request
- Тип запроса: POST, GET, DELETE, PUT, PATCH. Адрес пути: /users/registrations
- Адрес хоста: host:booking.com
- Headers: авторизационный токен, тип данных который отправляется, формат данных (вспомогательные хедеры)
- Тело запроса: Файл, html, json и т.д

## HTTP response
- Код ответа: 200 OK, 201 OK, 500 ISE и т.д
- Headers: дата, тип данных и т.д
- Тело ответа

### Коды ответа
- 1XX: информационные
- 2XX: успешные
- 3XX: перенаправление
- 4XX: ошибка клиента
- 5XX: ошибка сервера

## Rest
Representational State Transfer - архитектурный стиль, использующий HTTP для взаимодействия с ресурсами
Принципы REST:
- клиент - сервер взаимодействие
- Statless сервер: сервер не должен запоминать запросы клиента
- Кэширование запросов: клиент может запомнить какие то запросы
- Единый интерфейс: все является ресурсами. У каждого ресурса свой путь
- Многослойная система: между клиентом и сервером может быть цепочка других посредников

### Json
JavaScript object notation - легковесный человеко-читаемый формат для обмена данными. Используется для передачи данных между клиентом и сервером в веб приложении, особенно при Rest взаимодействии

## Устройство Spring Web
Существует Connector который слушает определённый запрос, затем он перераспределяет запросы на потоки (под капотом - ThreadPoolExecutor). Каждый поток попадает на DispatcherServlet (выполняет основную маршрутизацию и обработку запросов) - явлвяется частью Spring и работает внутри контейнера Tomcat. Затем контроллер выполняет основную логику и отправляет ответ. Если вылетело исключение, Dispatcher Servlet вызывает Exception Handler (но всё это Dispatcher servlet делает не напрямую)

# Spring Boot starter Data JPA, Hibernate, Docker и базы данных
## JPA 
Java Persistence API - это спецификация для управления реляционными данными в Java приложениях
JPA представляет набор API и аннотаций для маппинга объектов Java в реляционные базы данных (ORM)

## ORM
позволяет работать с базой данных, используя ООП
Снижает количество ошибок с ручным написанием sql-запросов
Hibernate - стандарт    

## Docker
Docker - платформа для разработки, доставки и эксплуатации приложений с использованием контейнеризации
Позволяет разработчикам упаковывать приложения и все их зависимости в контейнеры, которые можно запускать в любой среде, обеспечивая стабильную работу вне зависимости от различий в конфигурации систем (неважно какая ОС и т.д)

### Образы и контейнеры
Dockerfile - текстовый файл, содержащий набор инструкций для сборки Docker образа
Docker image - шаблон, который используется для создания контейнеров. Образ содержит всё, что необходимо для запуска приложений, включая код, runtime, библиотеки, зависимости и параметры конфигураций
Docker Container - это экземпляр, созданный на основе Docker образа

## Слои приложения
- Слой API (контроллер), занимается обработкой HTTP и корректно на них отвечать
- Service (может содержаться из сотни сервисов), выполняет основую работу
- Database (выполняет работу в базе данных)

Каждый слой имеет свою ответственность и представляет соответствующий набор методов, который должны выполнять работу, соответствующую слою

## Аннотация @Query
Представляет способ определения запросов к базе данных непосредственно в интерфейсе репозитория

Пример использования: просто пишем запрос внутри аннотации и Spring выполнит его при вызове метода
```java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    @Query("SELECT u FROM User u WHERE u.email = :email")
    USER findByEmail(@Param("email") String email);

    @Modifying
    @Query("UPDATE User u SET u.active = false WHERE u.lastLogin < :date")
    int deactivateUsersNotLoggedInSince(@Param("date") LocalDate date);
}
```
Представляет функции:
- Поддержка JPQL (Java Persistence Query Language) и SQL
- Использование именованных параметров
- Возможность писать модифицирующие запросы
